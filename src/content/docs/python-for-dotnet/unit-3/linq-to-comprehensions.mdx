В C# работата с колекции минава през LINQ: `Where`, `Select`, `OrderBy`, `ToList`. В Python няма LINQ и няма extension methods. На тяхно място стоят **comprehensions**, които са част от синтаксиса на езика, и няколко вградени функции като `sum`, `any` и `sorted`.

Почти всяка LINQ заявка има пряк превод. Темите са шест. Всяка започва с код на C# и същия код на Python, а завършва с един въпрос. Накрая те чакат три задачи.

Примерите работят с едни и същи данни. Запиши ги във файл, ако искаш да пробваш всеки от тях:

```python title="orders.py"
from dataclasses import dataclass

@dataclass
class Order:
    id: int
    customer: str
    total: float
    paid: bool


orders = [
    Order(1, "Ana", 120.0, True),
    Order(2, "Boris", 35.5, False),
    Order(3, "Ana", 80.0, True),
    Order(4, "Vera", 210.0, True),
]
```

## List comprehension: `Where` и `Select` в един израз

<Compare>

```csharp title="C#"
var names = orders
    .Where(o => o.Paid)
    .Select(o => o.Customer)
    .ToList();
// ["Ana", "Ana", "Vera"]
```

```python title="Python"
names = [
    o.customer
    for o in orders
    if o.paid
]
# ['Ana', 'Ana', 'Vera']
```

</Compare>

List comprehension има три части и те стоят винаги в този ред:

1. **Какво взимаш** от всеки елемент: `o.customer`. Това е `Select`.
2. **Откъде**: `for o in orders`.
3. **Кои елементи**: `if o.paid`. Това е `Where` и може да липсва.

Квадратните скоби наоколо казват, че резултатът е нов `list`. Те са твоят `ToList()`.

В началото редът обърква, защото резултатът стои преди източника. Чети от `for`: за всяка поръчка, ако е платена, вземи клиента. Къс comprehension се пише на един ред:

```python
names = [o.customer for o in orders if o.paid]
```

Това е следният цикъл, записан като израз:

```python
names = []
for o in orders:
    if o.paid:
        names.append(o.customer)
```

Двете части могат да стоят и поотделно. `[o.total for o in orders]` е само `Select`, а `[o for o in orders if o.total > 100]` е само `Where`. Първата част е задължителна дори когато е самият елемент.

За разлика от LINQ заявката, list comprehension се изпълнява веднага и докрай. Отложеният вариант е четвъртата тема.

### `if` на две места

`if` в края филтрира. Когато всеки елемент трябва да даде резултат, но различен според условие, в първата част слагаш тернарния израз от първия урок:

```python
labels = ["paid" if o.paid else "open" for o in orders]
# ['paid', 'open', 'paid', 'paid']
```

В C# това е `Select(o => o.Paid ? "paid" : "open")`. Двете форми лесно се бъркат. `if` с `else` стои пред `for` и избира стойност. `if` без `else` стои след `for` и маха елементи.

Ще срещнеш и функциите `map()` и `filter()`, които правят същото с подадена функция. Работят, но обичайният запис е comprehension. Той е за създаване на нова колекция. Когато искаш действие за всеки елемент, например `print`, пиши обикновен `for`.

## dict и set comprehensions

<Compare>

```csharp title="C#"
var totals = orders.ToDictionary(
    o => o.Id,
    o => o.Total);

var customers = orders
    .Select(o => o.Customer)
    .ToHashSet();
```

```python title="Python"
totals = {
    o.id: o.total
    for o in orders
}

customers = {
    o.customer
    for o in orders
}
```

</Compare>

Формата решава типа, както при литералите от първия урок. Къдрави скоби с `ключ: стойност` дават `dict`, а къдрави скоби с една стойност дават `set`:

```python
print(totals)      # {1: 120.0, 2: 35.5, 3: 80.0, 4: 210.0}
print(customers)   # {'Ana', 'Boris', 'Vera'}, in some order
```

Set comprehension е и твоят `Distinct()`: Ana има две поръчки, но в резултата е веднъж. Редът в един `set` не е гарантиран. Когато ти трябва подреден списък без повторения, напиши `sorted(customers)`.

**Повтарящ се ключ не е грешка.** `ToDictionary` хвърля `ArgumentException` при втори еднакъв ключ. Dict comprehension мълчаливо оставя последната стойност:

```python
by_customer = {o.customer: o.total for o in orders}
# {'Ana': 80.0, 'Boris': 35.5, 'Vera': 210.0}
```

Поръчката на Ana за 120 изчезна без никакво съобщение. Когато ключовете могат да се повтарят, ти трябва групиране, а то е в последната тема.

Съществуващ `dict` се обхожда с `.items()`, което дава двойките ключ и стойност:

```python
stock = {"tea": 12, "milk": 0, "jam": 3}

available = {name: count for name, count in stock.items() if count > 0}
# {'tea': 12, 'jam': 3}
```

Comprehension за tuple няма. Същият запис в кръгли скоби е нещо друго и за него е четвъртата тема.


## Няколко източника: `SelectMany`, `Zip` и индекси

<Compare>

```csharp title="C#"
List<List<string>> baskets = [
    ["tea", "milk"],
    ["bread"],
];

var items = baskets
    .SelectMany(b => b)
    .ToList();
// ["tea", "milk", "bread"]
```

```python title="Python"
baskets = [
    ["tea", "milk"],
    ["bread"],
]

items = [
    item
    for basket in baskets
    for item in basket
]
# ['tea', 'milk', 'bread']
```

</Compare>

Comprehension може да има повече от един `for`. Те се пишат в реда, в който биха стояли вложените цикли: външният е първи.

```python
items = []
for basket in baskets:
    for item in basket:
        items.append(item)
```

Обърнеш ли ги, `basket` се ползва, преди да е получил стойност, и Python спира с `NameError`. Два `for`-а още се четат. При три, или при два с условия, обикновеният цикъл е по-ясен.

Източникът може да е и нещо повече от една колекция. Две вградени функции покриват случаите, за които LINQ има отделни методи:

```python
names = ["Ana", "Boris", "Vera"]
scores = [91, 78, 85]

results = [f"{name}: {score}" for name, score in zip(names, scores)]
# ['Ana: 91', 'Boris: 78', 'Vera: 85']

ranked = [f"{place}. {name}" for place, name in enumerate(names, start=1)]
# ['1. Ana', '2. Boris', '3. Vera']
```

- **`zip(a, b)`** върви по двете колекции едновременно и дава двойки, както `Zip`. Спира при по-късата.
- **`enumerate(items)`** дава двойки от индекс и елемент. Това е `Select((item, index) => ...)`, само че индексът е първи. Броенето започва от 0, освен ако не подадеш `start`.

И двете работят и в обикновен `for`. Класическият `for (int i = 0; i < n; i++)` в Python е `for i in range(n)`. Когато обаче индексът ти трябва само за да стигнеш до елемента, `enumerate` е по-краткият запис.

## Generator expressions: отложеното изпълнение

<Compare>

```csharp title="C#"
var totals = orders
    .Where(o => o.Paid)
    .Select(o => o.Total);
// nothing has run yet

var revenue = totals.Sum();  // 410
```

```python title="Python"
totals = (
    o.total
    for o in orders
    if o.paid
)
# nothing has run yet

revenue = sum(totals)  # 410.0
```

</Compare>

Същият запис в кръгли скоби е **generator expression**. Той не създава списък. Връща обект, който смята елементите един по един, когато някой ги поиска: LINQ заявка без `ToList()`.

Най-често ще го подаваш направо на функция, която изчерпва елементите. Тогава вторият чифт скоби отпада:

```python
revenue = sum(o.total for o in orders if o.paid)
```

Междинен списък не се създава, а това има значение при милион реда или при голям файл.

Тук е и разликата, в която се спъват хората, дошли от LINQ. Заявката в C# е `IEnumerable` и се изпълнява отново при всяко обхождане. Generator се изчерпва след първото:

```python
totals = (o.total for o in orders if o.paid)

print(sum(totals))   # 410.0
print(sum(totals))   # 0
```

Вторият ред не дава грешка, а нула. Generator прилича повече на `IEnumerator`: върви само напред и не се връща в началото. По същата причина няма дължина и индекси, и `len(totals)` хвърля `TypeError`.

Изборът между двата вида скоби е прост:

- **`[...]`**, когато резултатът ти трябва повече от веднъж, или ти трябват `len()` и индекси.
- **`(...)`**, когато резултатът отива веднага в `sum`, `max`, `sorted`, `join` или в един `for`.

Как се пишат собствени generators с `yield`, е темата на следващия урок.

## Агрегати: `sum`, `any`, `max` и параметърът `key`

<Compare>

```csharp title="C#"
var revenue = orders
    .Sum(o => o.Total);

var hasDebt = orders
    .Any(o => !o.Paid);

var biggest = orders
    .MaxBy(o => o.Total);
```

```python title="Python"
revenue = sum(
    o.total for o in orders
)

has_debt = any(
    not o.paid for o in orders
)

biggest = max(
    orders, key=lambda o: o.total
)
```

</Compare>

В LINQ всеки агрегат е метод, който приема lambda. В Python агрегатите са обикновени функции, които приемат нещо за обхождане. Проекцията и филтърът влизат в generator expression-а, който им подаваш, така че моделът е един: `функция(израз for x in xs if условие)`.

`max`, `min` и `sorted` имат и параметър `key`. Той е функция, която се вика за всеки елемент, а резултатът ѝ се използва за сравнението. `lambda o: o.total` е `o => o.Total`: един израз, без `return`. Когато логиката не се събира в един израз, пишеш обикновена функция с `def` и подаваш името ѝ без скоби: `key=order_weight`.

Внимавай какво връща `max`. `max(orders, key=lambda o: o.total)` връща **поръчката**, както `MaxBy`. `max(o.total for o in orders)` връща **числото**, както `Max`.

Ето превода на методите, които ще ти трябват най-често:

| LINQ | Python |
| --- | --- |
| `xs.Count()` | `len(xs)` |
| `xs.Count(x => x.Paid)` | `sum(1 for x in xs if x.paid)` |
| `xs.Sum(x => x.Total)` | `sum(x.total for x in xs)` |
| `xs.Average(x => x.Total)` | `mean(x.total for x in xs)` |
| `xs.Min()`, `xs.Max()` | `min(xs)`, `max(xs)` |
| `xs.MinBy(x => x.Total)` | `min(xs, key=lambda x: x.total)` |
| `xs.Any(x => x.Paid)` | `any(x.paid for x in xs)` |
| `xs.All(x => x.Paid)` | `all(x.paid for x in xs)` |
| `xs.Any()` | `if xs:` |
| `xs.Contains(value)` | `value in xs` |
| `xs.First(x => x.Paid)` | `next(x for x in xs if x.paid)` |
| `xs.FirstOrDefault(x => x.Paid)` | `next((x for x in xs if x.paid), None)` |
| `xs.Take(3)`, `xs.Skip(3)` | `xs[:3]`, `xs[3:]` |
| `xs.Concat(ys)` | `xs + ys` |
| `xs.Distinct()` | `set(xs)`, а със запазен ред `list(dict.fromkeys(xs))` |
| `string.Join(", ", xs)` | `", ".join(xs)` |

Няколко бележки към таблицата:

- **`mean`** идва от стандартната библиотека: `from statistics import mean`.
- **`next(...)`** взима първия елемент на generator. Вторият аргумент е стойността, когато няма нито един. Без него празният резултат хвърля `StopIteration`, както `First()` хвърля `InvalidOperationException`.
- **`max` и `min` от празна колекция** хвърлят `ValueError`. `max(xs, default=0)` връща стойност вместо това.
- **`join`** е метод на разделителя, а не на списъка, и приема само низове. За числа: `", ".join(str(n) for n in numbers)`.
- **`if xs:`, `len(xs)` и `xs[:3]`** работят за `list`. Generator няма дължина и индекси, затова първо го превърни с `list(...)`.

## Подреждане и групиране

<Compare>

```csharp title="C#"
var ranked = orders
    .OrderByDescending(o => o.Total)
    .ToList();
```

```python title="Python"
ranked = sorted(
    orders,
    key=lambda o: o.total,
    reverse=True,
)
```

</Compare>

`sorted` приема каквото и да е за обхождане и връща нов, подреден `list`. Оригиналът остава непипнат. Редът се задава със същия `key` като при `max`, а `reverse=True` го обръща.

Списъците имат и метод `sort()`. Той подрежда на място, както `List<T>.Sort()`, и връща `None`. Оттам идва една позната грешка: `orders = orders.sort()` оставя в `orders` стойността `None`.

За `ThenBy` ключът става tuple. Tuples се сравняват елемент по елемент, така че първото поле води, а второто решава при равенство:

```python
ranked = sorted(orders, key=lambda o: (o.customer, -o.total))
# Ana 120.0, Ana 80.0, Boris 35.5, Vera 210.0
```

Минусът пред числото обръща посоката само за него: клиентите са по азбучен ред, а поръчките на всеки са от най-голямата към най-малката. За текст минус няма. Тогава подреждаш два пъти, първо по второстепенния ключ, защото `sorted` пази реда на равните елементи.

### Групиране

Готов `GroupBy` няма. Групите се събират в `dict`, в който ключът е това, по което групираш, а стойността е списък. `defaultdict` от модула `collections` спестява проверката дали ключът вече съществува:

```python
from collections import defaultdict

groups = defaultdict(list)

for o in orders:
    groups[o.customer].append(o)

spent = {
    customer: sum(o.total for o in group)
    for customer, group in groups.items()
}
# {'Ana': 200.0, 'Boris': 35.5, 'Vera': 210.0}
```

`defaultdict(list)` е `dict`, който при липсващ ключ сам създава стойността, като вика подадената функция. `list()` връща празен списък, така че `append` работи още първия път. С `defaultdict(float)` липсващият ключ започва от `0.0`, което стига за суми.

За самото броене има и по-кратък път:

```python
from collections import Counter

counts = Counter(o.customer for o in orders)

print(counts["Ana"])           # 2
print(counts.most_common(1))   # [('Ana', 2)]
```

:::caution[itertools.groupby не е GroupBy]
В стандартната библиотека има функция `itertools.groupby`, но тя групира само **съседни** елементи. Ако данните не са подредени по същия ключ, получаваш по няколко групи за една стойност. За `GroupBy` от LINQ ползвай `dict`.
:::

```python title="grades.py"
def averages(grades: dict[str, list[int]]) -> dict[str, float]:
    return {
        name: sum(marks) / len(marks)
        for name, marks in grades.items()
        if marks
    }


grades = {
    "Ana": [6, 5, 6],
    "Boris": [4, 3],
    "Vera": [],
    "Dimo": [5, 6],
}

result = averages(grades)
name, average = max(result.items(), key=lambda pair: pair[1])

print(f"{name}: {average:.2f}")
```

```python title="sales.py"
from collections import defaultdict


def top_cities(
    sales: list[tuple[str, float]],
    count: int,
) -> list[tuple[str, float]]:
    totals: defaultdict[str, float] = defaultdict(float)

    for city, amount in sales:
        totals[city] += amount

    ranked = sorted(totals.items(), key=lambda pair: pair[1], reverse=True)
    return ranked[:count]


sales = [
    ("Sofia", 120.0),
    ("Plovdiv", 80.0),
    ("Sofia", 45.5),
    ("Varna", 150.0),
    ("Plovdiv", 30.0),
    ("Burgas", 60.0),
]

for city, total in top_cities(sales, 2):
    print(f"{city}: {total:.2f}")
```

Това е `GroupBy`, `OrderByDescending` и `Take` от LINQ. Групирането е цикъл с `dict`, а подреждането и отрязването са по един израз.

## Обобщение

- `[израз for x in xs if условие]` е `Select`, `Where` и `ToList` в едно. `if` с `else` пред `for` избира стойност, а `if` след `for` филтрира.
- Къдравите скоби дават `dict` или `set`. При повтарящ се ключ остава последната стойност, без грешка.
- Няколко `for`-а в един comprehension са `SelectMany`. `zip` и `enumerate` дават двойки и индекси.
- Кръглите скоби дават **generator expression**: отложено изпълнение, но само за едно обхождане.
- `sum`, `any`, `all`, `min` и `max` приемат generator expression, а `key` казва по какво да се сравнява.
- `sorted()` връща нов списък, а `sort()` подрежда на място и връща `None`. Групирането става с `dict`, `defaultdict` или `Counter`.

Следващият урок е за iterators и generators: какво стои зад `for` и как `yield return` от C# се превръща в `yield`. Той се подготвя в момента.
