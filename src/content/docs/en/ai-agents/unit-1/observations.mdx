An Observation is **how an Agent learns what happened after its action**. It is the third step of the cycle.

In practice, an Observation is **the text the tool returns**: data from an API, an error message, a line from a log. To a .NET developer it is the return value of the C# method, turned into text. In the previous section you saw it as the line `Observation: the weather in New York is sunny with low temperatures.`

In the Observation phase, the Agent:

- **Collects feedback:** it receives the data, or confirmation of whether the action succeeded.
- **Appends the result to the conversation:** the Observation is written at the end of the conversation and so updates the Agent's "memory".
- **Adapts its strategy:** the next Thought already builds on this new information.

:::tip[An error is an Observation too]
If the tool fails, don't hide the error. Return it as text, just as we did with `Unknown tool: GetTime` in the previous section. The model will read it and will often fix its action on the next round by itself.
:::

## Types of Observations

Observations can be very different. You can think of them as the "logs" of a tool:

| Type of Observation | Example |
| --- | --- |
| System Feedback | Error messages, success notifications, status codes |
| Data Changes | Database updates, file system modifications |
| Environmental Data | Sensor readings, system metrics |
| Response Analysis | API responses, query results, computation outputs |

## How are the results appended?

After the model asks for an action, the Agent's code does three things, in this order:

1. **It parses the action** to find out which tool to call and with what arguments.
2. **It runs the tool.**
3. **It appends the result** to the conversation as an **Observation**.

You wrote the first two steps in the previous section. The third is just one more message in the list. Here is what the conversation looks like after it:

| Role | Content |
| --- | --- |
| `system` | The rules of the cycle and the tool descriptions. |
| `user` | `What's the weather in New York?` |
| `assistant` | `Thought: ...` and `Action: {...}`, as the model wrote them. |
| `user` | `Observation: the weather in New York is sunny with low temperatures.` |

Then the whole conversation goes back to the model. It sees its action and the result of it, and decides whether it needs more information or is ready with the final answer.

In this simple variant the Observation is added as a `user` message. With function calling there is a separate role for tool results, but the idea is the same.
