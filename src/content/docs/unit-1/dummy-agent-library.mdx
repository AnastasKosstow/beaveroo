## Serverless API

В екосистемата на Hugging Face има удобна услуга — [Inference Providers](https://huggingface.co/docs/inference-providers/index) — която ти позволява лесно да изпълняваш inference с много модели. Не е необходима инсталация или deployment. API-то е съвместимо с OpenAI Chat Completions формата, което означава, че от .NET можем да го извикаме с обикновен `HttpClient`.

```csharp
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json;
using System.Text.Json.Nodes;

// Нужен ти е token от https://hf.co/settings/tokens — увери се, че избираш тип 'read'.
// Задай го като environment variable HF_TOKEN (никога не го записвай в кода):
//   PowerShell:  $env:HF_TOKEN = "hf_..."
//   bash/zsh:    export HF_TOKEN="hf_..."
string hfToken = Environment.GetEnvironmentVariable("HF_TOKEN")
    ?? throw new InvalidOperationException("Задай environment variable HF_TOKEN.");

const string Model = "moonshotai/Kimi-K2.5";

using var client = new HttpClient { BaseAddress = new Uri("https://router.huggingface.co/v1/") };
client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", hfToken);
```

Използваме метода `chat/completions`, тъй като това е удобен и надежден начин да се приложат chat templates (сървърът ги прилага вместо нас). Нашата „dummy библиотека“ е една-единствена функция, която изпраща списък от messages и връща текста на отговора:

```csharp
// Изпраща messages към Chat Completions API и връща съдържанието на отговора.
async Task<string> ChatAsync(JsonArray messages, int maxTokens = 1024, string? stop = null)
{
    var payload = new JsonObject
    {
        ["model"] = Model,
        ["messages"] = messages.DeepClone(),
        ["max_tokens"] = maxTokens,
        ["stream"] = false,
        // Специфично за Kimi-K2.5: изключваме режима на „мислене“, за да получим директен отговор.
        ["thinking"] = new JsonObject { ["type"] = "disabled" },
    };

    if (stop is not null)
    {
        payload["stop"] = new JsonArray(stop);
    }

    using HttpResponseMessage response = await client.PostAsJsonAsync("chat/completions", payload);
    response.EnsureSuccessStatusCode();

    JsonNode? result = await response.Content.ReadFromJsonAsync<JsonNode>();
    return result?["choices"]?[0]?["message"]?["content"]?.GetValue<string>() ?? string.Empty;
}
```

Да я изпробваме:

```csharp
var messages = new JsonArray
{
    new JsonObject { ["role"] = "user", ["content"] = "The capital of France is" },
};

string output = await ChatAsync(messages, maxTokens: 1024);
Console.WriteLine(output);
```

изход:

```text
Paris.
```

Методът chat е ПРЕПОРЪЧИТЕЛНИЯТ метод, който да използваш, за да осигуриш гладък преход между моделите.

:::note
Ако предпочиташ друг модел, смени константата `Model` с произволен чат модел от [Inference Providers](https://huggingface.co/models?inference_provider=all&sort=trending) — например `Qwen/Qwen3-235B-A22B-Instruct-2507` или `openai/gpt-oss-120b`. Параметърът `thinking` е специфичен за Kimi-K2.5; при други модели го премахни.
:::

## Dummy Agent

В предишните секции видяхме, че същността на една agent библиотека е да добавя информация към system prompt-а.

Този system prompt е малко по-сложен от този, който видяхме по-рано, но вече съдържа:

1. **Информация за tools**
2. **Инструкции за цикъла** (Thought → Action → Observation)

```csharp
// Този system prompt е малко по-сложен и всъщност вече съдържа описанието на функцията.
// Тук приемаме, че текстовото описание на tools вече е добавено.

example use :

{
  "action": "get_weather",
  "action_input": {"location": "New York"}
}


ALWAYS use the following format:

Question: the input question you must answer
Thought: you should always think about one action to take. Only one action at a time in this format:
Action:

$JSON_BLOB (inside markdown cell)
```

Виждаш ли проблема?

> В този момент моделът халюцинира, защото произвежда измислен „Observation“ — отговор, който генерира сам, вместо той да е резултат от реално извикване на функция или tool.
> За да предотвратим това, спираме генерирането точно преди „Observation:“.
> Това ни позволява ръчно да изпълним функцията (например `GetWeather`) и след това да вмъкнем реалния изход като Observation.

```csharp
// Отговорът беше халюциниран от модела. Трябва да спрем, за да изпълним реално функцията!
output = await ChatAsync(
    messages,
    maxTokens: 150,
    stop: "Observation:" // Спираме, преди да бъде извикана каквато и да е реална функция
);

Console.WriteLine(output);
```

изход:

````text
Thought: To answer the question, I need to get the current weather in London.
Action:
```
{
  "action": "get_weather",
  "action_input": {"location": "London"}
}


````
