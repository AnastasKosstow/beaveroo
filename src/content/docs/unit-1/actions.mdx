Actions са конкретните стъпки, които **AI agent предприема, за да взаимодейства със средата си**.

Независимо дали става дума за търсене на информация в интернет или за управление на физическо устройство, всеки action е целенасочена операция, изпълнена от agent-а.

Например agent, който помага при обслужване на клиенти, може да извлече данни за клиента, да предложи статии за поддръжка или да прехвърли проблема към човек.

## Типове Actions на Agent

Има множество типове Agents, които предприемат actions по различен начин:

| Тип Agent | Описание |
|-----------|----------|
| JSON Agent | Action-ът, който трябва да се предприеме, е описан във формат JSON. |
| Code Agent | Agent-ът пише блок код, който се интерпретира външно. |
| Function-calling Agent | Подкатегория на JSON Agent, която е fine-tuned да генерира ново съобщение за всеки action. |

Самите actions могат да служат за много цели:

| Тип Action | Описание |
|------------|----------|
| Information Gathering | Търсене в интернет, заявки към бази данни или извличане на документи. |
| Tool Usage | Извикване на API, извършване на изчисления и изпълнение на код. |
| Environment Interaction | Манипулиране на дигитални интерфейси или управление на физически устройства. |
| Communication | Общуване с потребителите чрез чат или сътрудничество с други agents. |

LLM работи само с текст и го използва, за да опише action-а, който иска да предприеме, и параметрите, които да подаде на tool-а. За да работи agent-ът правилно, LLM трябва да СПРЕ да генерира нови tokens, след като е извел всички tokens, дефиниращи пълен Action. Това прехвърля контрола от LLM обратно към agent-а и гарантира, че резултатът може да бъде парснат — независимо дали целевият формат е JSON, код или function-calling.

## Подходът Stop and Parse

Един ключов метод за реализиране на actions е **подходът stop and parse**. Този метод гарантира, че изходът на agent-а е структуриран и предвидим:

1. **Генериране в структуриран формат**:

Agent-ът извежда планирания action в ясен, предварително определен формат (JSON или код).

2. **Спиране на по-нататъшното генериране**:

След като текстът, дефиниращ action-а, е изведен, **LLM спира да генерира допълнителни tokens**. Това предотвратява излишен или грешен изход.

3. **Парсване на изхода**:

Външен парсер чете форматирания action, определя кой Tool да бъде извикан и извлича необходимите параметри.

Например agent, който трябва да провери времето, може да изведе:

```json
Thought: I need to check the current weather for New York.
Action :
{
  "action": "get_weather",
  "action_input": {"location": "New York"}
}
```

Framework-ът след това лесно може да парсне името на функцията, която да извика, и аргументите, които да приложи.

Този ясен, машинно четим формат минимизира грешките и позволява на външните tools точно да обработят командата на agent-а.

Бележка: Function-calling agents работят по сходен начин, като структурират всеки action така, че определена функция да бъде извикана с правилните аргументи. Ще разгледаме тези типове Agents по-задълбочено в следващ Unit.

## Code Agents

Алтернативен подход е използването на *Code Agents*.
Идеята е: **вместо да извежда обикновен JSON обект**, Code Agent генерира **изпълним блок код — обикновено на език от високо ниво като Python**. Самата концепция не зависи от езика: в .NET света такъв код може да бъде C# скрипт, изпълняван чрез [Roslyn scripting API](https://github.com/dotnet/roslyn/blob/main/docs/wiki/Scripting-API-Samples.md) или `dotnet-script`.

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/code-vs-json-actions.png" alt="Code Agents" />

Този подход предлага няколко предимства:

- **Изразителност:** Кодът може естествено да представя сложна логика, включително цикли, условия и вложени функции, предоставяйки по-голяма гъвкавост от JSON.
- **Модулност и преизползваемост:** Генерираният код може да включва функции и модули, които се преизползват в различни actions или задачи.
- **По-лесно дебъгване:** При добре дефиниран синтаксис на езика за програмиране грешките в кода често са по-лесни за откриване и коригиране.
- **Директна интеграция:** Code Agents могат да се интегрират директно с външни библиотеки и API, позволявайки по-сложни операции като обработка на данни или вземане на решения в реално време.

Трябва да имаш предвид, че изпълнението на генериран от LLM код може да носи рискове за сигурността — от prompt injection до изпълнение на зловреден код.
Затова се препоръчва да се използват AI agent frameworks като `smolagents`, които включват защити по подразбиране. В .NET няма еквивалентна вградена „пясъчна кутия“ (sandbox) за C# скриптове, затова генерираният код трябва да се изпълнява в изолирана среда — отделен процес с ограничени права или контейнер.
Ако искаш да научиш повече за рисковете и как да ги ограничиш, [разгледай тази специална секция](https://huggingface.co/docs/smolagents/tutorials/secure_code_execution).

Например Code Agent, натоварен със задачата да извлече времето, може да генерира следния C# фрагмент:

```csharp
// Пример за Code Agent: извличане на информация за времето
using System.Text.Json;

using var http = new HttpClient();

async Task<string> GetWeather(string city)
{
    string apiUrl = $"https://api.weather.com/v1/location/{city}?apiKey=YOUR_API_KEY";
    using HttpResponseMessage response = await http.GetAsync(apiUrl);

    if (response.IsSuccessStatusCode)
    {
        using JsonDocument data = JsonDocument.Parse(await response.Content.ReadAsStringAsync());
        return data.RootElement.TryGetProperty("weather", out JsonElement weather)
            ? weather.ToString()
            : "No weather information available";
    }

    return "Error: Unable to fetch weather data.";
}

// Изпълняваме функцията и подготвяме финалния отговор
string result = await GetWeather("New York");
string finalAnswer = $"The current weather in New York is: {result}";
Console.WriteLine(finalAnswer);
```

В този пример Code Agent-ът:

- Извлича данни за времето **чрез API извикване**,
- Обработва отговора,
- И използва `Console.WriteLine()`, за да изведе финалния отговор.

Този метод **също следва подхода stop and parse**, като ясно очертава блока код и сигнализира кога изпълнението е завършено (тук — чрез извеждането на `finalAnswer`).

Научихме, че Actions свързват вътрешното reasoning на agent-а с неговите взаимодействия с реалния свят, като изпълняват ясни, структурирани задачи — чрез JSON, код или function calls.

Това целенасочено изпълнение гарантира, че всеки action е прецизен и готов за външна обработка чрез подхода stop and parse. В следващата секция ще разгледаме Observations, за да видим как agents улавят и интегрират обратната връзка от своята среда.
