## Какво е Microsoft.Extensions.AI?

В оригиналния курс този Agent се изгражда със `smolagents` — лека Python библиотека на Hugging Face. В .NET света нейната роля ще играе [`Microsoft.Extensions.AI`](https://learn.microsoft.com/dotnet/ai/microsoft-extensions-ai) — библиотека, която **предоставя framework за лесно разработване на твоите agents**.

Тази лека библиотека е проектирана с мисъл за простота, но абстрахира голяма част от сложността при изграждането на Agent, което ти позволява да се фокусираш върху проектирането на поведението му. Основните ѝ градивни елементи са:

- `IChatClient` — единен интерфейс към всеки LLM доставчик (OpenAI, Azure, Ollama, Hugging Face Inference Providers и др.);
- `AIFunctionFactory` — превръща обикновен C# метод в Tool с име, описание и JSON Schema (видяхме го в секцията [Tools](/unit-1/tools/));
- `UseFunctionInvocation()` — middleware, който автоматично изпълнява цикъла **Thought → Action → Observation**: когато моделът поиска tool, библиотеката го извиква, връща резултата като Observation и подава всичко обратно на модела, докато той не даде финален отговор.

Ще навлезем по-дълбоко в тези библиотеки в следващия Unit. Междувременно можеш да разгледаш <a href="https://learn.microsoft.com/dotnet/ai/quickstarts/use-function-calling" target="_blank">ръководството за function calling в .NET</a> или <a href="https://github.com/dotnet/extensions/tree/main/src/Libraries/Microsoft.Extensions.AI" target="_blank">хранилището в GitHub</a>, а за оригиналния подход — <a href="https://huggingface.co/blog/smolagents" target="_blank">блог публикацията за smolagents</a>.

Накратко, `smolagents` се фокусира върху **CodeAgent** — вид agent, който изпълнява **„Actions“** чрез блокове код и след това **„наблюдава“** резултатите от изпълнението им. Нашият .NET Agent ще бъде **Function-calling Agent** (виж секцията [Actions](/unit-1/actions/)): моделът генерира структурирано извикване на tool, а `Microsoft.Extensions.AI` го изпълнява вместо нас.

Ето пример от оригиналния курс за това, което ще изградим!

Там Agent-ът е снабден с **Image generation tool** и е помолен да генерира изображение на котка.

Agent-ът ще има **същото поведение като собственоръчно направения, който изградихме по-рано**: той ще **мисли, действа и наблюдава в цикъл**, докато не достигне до финален отговор:

## Да изградим своя Agent!

В оригиналния курс се започва от готов Hugging Face Space ([First_agent_template](https://huggingface.co/spaces/agents-course/First_agent_template) — благодарности на <a href="https://huggingface.co/m-ric" target="_blank">Aymeric</a> за шаблона! 🙌). В .NET версията ще създадем проекта локално:

```bash
dotnet new console -n FirstAgent
cd FirstAgent
dotnet add package Microsoft.Extensions.AI
dotnet add package Microsoft.Extensions.AI.OpenAI
dotnet add package YamlDotNet
```

След това трябва да добавиш своя Hugging Face API token, за да може agent-ът да достъпва API-то на модела. В Space това се прави чрез *Settings → Variables and Secrets → New Secret* с име `HF_TOKEN`; локално използваме environment variable със същото име:

1. Първо вземи своя Hugging Face token от [https://hf.co/settings/tokens](https://hf.co/settings/tokens) с права за inference, ако все още нямаш такъв
2. Задай го като environment variable в терминала, от който ще стартираш приложението:

```powershell
# PowerShell
$env:HF_TOKEN = "hf_..."
```

```bash
# bash / zsh
export HF_TOKEN="hf_..."
```

3. Никога не записвай token-а в кода и не го качвай в Git.

В този урок единственият файл, който ще трябва да променяш, е **`Program.cs`** (плюс файлът `prompts.yaml` със system prompt-а). В оригиналния шаблон това е файлът [app.py](https://huggingface.co/spaces/agents-course/First_agent_template/blob/main/app.py).

Да разгледаме кода заедно:

- Файлът започва с няколко прости, но необходими `using` директиви

```csharp
using System.ClientModel;
using System.ComponentModel;
using System.Text.Json;
using Microsoft.Extensions.AI;
using OpenAI;
using YamlDotNet.Serialization;
```

Както споменахме, ще използваме директно `IChatClient` и `AIFunctionFactory` от **Microsoft.Extensions.AI**.

### Tools

А сега към tools! Ако искаш да си припомниш какво са tools, не се колебай да се върнеш към секцията [Tools](/unit-1/tools/) на курса.

```csharp
/// <summary>Tools, с които разполага Alfred.</summary>
public static class AlfredTools
{
    // По-долу е пример за tool, който не прави нищо. Изненадай ни с креативността си!
    [Description("A tool that does nothing yet")]
    public static string MyCustomTool(
        [Description("the first argument")] string arg1,
        [Description("the second argument")] int arg2)
    {
        return "What magic will you build ?";
    }

    [Description("A tool that fetches the current local time in a specified timezone.")]
    public static string GetCurrentTimeInTimezone(
        [Description("A string representing a valid timezone (e.g., 'America/New_York').")] string timezone)
    {
        try
        {
            // Намираме часовата зона (поддържат се IANA имена като 'Europe/Sofia')
            TimeZoneInfo tz = TimeZoneInfo.FindSystemTimeZoneById(timezone);
            // Текущото време в тази зона
            DateTime localTime = TimeZoneInfo.ConvertTime(DateTime.UtcNow, tz);
            return $"The current local time in {timezone} is: {localTime:yyyy-MM-dd HH:mm:ss}";
        }
        catch (Exception e)
        {
            return $"Error fetching time for timezone '{timezone}': {e.Message}";
        }
    }
}
```

Tools са това, което те насърчаваме да изграждаш в тази секция! Даваме ти два примера:

1. **Неработещ dummy Tool**, който можеш да промениш, за да направиш нещо полезно.
2. **Реално работещ Tool**, който връща текущия час някъде по света. В Python оригиналът използва библиотеката `pytz`; в .NET вграденият `TimeZoneInfo` поддържа IANA имената на часовите зони.

За да дефинираш своя tool, е важно:

1. Да зададеш типове на входа и изхода на метода, както в `GetCurrentTimeInTimezone(string timezone)` → `string` (в C# това е задължително — компилаторът ти помага).
2. **Атрибут `[Description]` върху метода и върху всеки параметър**. `AIFunctionFactory` очаква всички аргументи да имат **текстово описание**, което подава на модела (в Python това е ролята на форматирания docstring).

### Agent-ът

Той използва [`openai/gpt-oss-120b`](https://huggingface.co/openai/gpt-oss-120b) като LLM engine. Това е много способен модел с поддръжка на function calling, до който ще достъпваме чрез Inference Providers (OpenAI-съвместим API). Оригиналът използва `Qwen/Qwen2.5-Coder-32B-Instruct` — можеш да смениш `ModelId` с всеки чат модел, който поддържа tool calling.

```csharp
// --- Token и модел ---------------------------------------------------------
string hfToken = Environment.GetEnvironmentVariable("HF_TOKEN")
    ?? throw new InvalidOperationException("Задай environment variable HF_TOKEN.");

const string ModelId = "openai/gpt-oss-120b";

// --- Моделът (Brain) -------------------------------------------------------
// Hugging Face Inference Providers предоставят OpenAI-съвместим API,
// затова използваме OpenAI клиента с друг Endpoint и го обвиваме като IChatClient.
IChatClient model = new OpenAIClient(
        new ApiKeyCredential(hfToken),
        new OpenAIClientOptions { Endpoint = new Uri("https://router.huggingface.co/v1") })
    .GetChatClient(ModelId)
    .AsIChatClient();

// --- Agent: модел + автоматичен цикъл Thought → Action → Observation --------
IChatClient agent = new ChatClientBuilder(model)
    .UseFunctionInvocation(configure: options => options.MaximumIterationsPerRequest = 6) // max_steps
    .Build();

var chatOptions = new ChatOptions
{
    Temperature = 0.5f,
    MaxOutputTokens = 2096,
    Tools =
    [
        AIFunctionFactory.Create(AlfredTools.GetCurrentTimeInTimezone),
        // Добави своите tools тук, например:
        // AIFunctionFactory.Create(AlfredTools.MyCustomTool),
    ],
};
```

Този Agent все още използва същото Chat Completions API, което видяхме в предишната секция — просто обвито в `IChatClient`! А `UseFunctionInvocation()` е точно цикълът, който в „Dummy Agent Library“ пишехме ръчно: спиране на генерирането при tool call, изпълнение на функцията, добавяне на Observation и ново извикване на модела — до `MaximumIterationsPerRequest` стъпки.

Ще дадем по-задълбочени примери, когато представим framework-а в Unit 2. Засега трябва да се фокусираш върху **добавянето на нови tools към списъка с tools** чрез свойството `Tools` на `ChatOptions`.

Например можеш да напишеш tool за търсене в интернет (аналог на `DuckDuckGoSearchTool` от оригинала) чрез `HttpClient` и публичен search API, или tool за генериране на изображения чрез задачата *text-to-image* на [Inference Providers](https://huggingface.co/docs/inference-providers/tasks/text-to-image) (аналог на `image_generation_tool`, който оригиналът зарежда от Hub).

**Добавянето на tools ще даде на твоя agent нови възможности** — бъди креативен тук!

### System Prompt-ът

System prompt-ът на agent-а се съхранява в отделен файл `prompts.yaml`. Този файл съдържа предварително дефинирани инструкции, които направляват поведението на agent-а.

Съхраняването на prompts в YAML файл позволява лесно персонализиране и преизползване между различни agents или случаи на употреба. В .NET го четем с библиотеката `YamlDotNet`:

```yaml title="prompts.yaml"
system_prompt: |
  You are Alfred, a helpful and polite AI assistant.
  Solve the user's task as best you can. You have access to tools: when a tool can help,
  call it, read its result (the Observation), and only then write your final answer.
  Think step by step before acting. Never invent tool results.
```

```csharp
// --- System prompt от prompts.yaml -----------------------------------------
var deserializer = new DeserializerBuilder().Build();
var promptTemplates = deserializer.Deserialize<Dictionary<string, string>>(File.ReadAllText("prompts.yaml"));

List<ChatMessage> history = [new(ChatRole.System, promptTemplates["system_prompt"])];
```

За да бъде файлът копиран до изпълнимия файл, добави в `FirstAgent.csproj`:

```xml title="FirstAgent.csproj"
<ItemGroup>
  <None Update="prompts.yaml" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

Можеш да разгледаш [структурата на оригиналния Space](https://huggingface.co/spaces/agents-course/First_agent_template/tree/main), за да видиш къде се намира `prompts.yaml` там и как е организиран.

### Потребителският интерфейс

Оригиналът използва `GradioUI(agent).launch()` — уеб чат интерфейс. В .NET най-простият еквивалент е конзолен чат цикъл; по-късно можеш да го замениш с Blazor или ASP.NET Core приложение.

```csharp
// --- Конзолен чат (вместо GradioUI) ----------------------------------------
Console.WriteLine("Alfred е готов. Напиши въпрос (или 'exit'):");

while (true)
{
    Console.Write("\nYou: ");
    string? input = Console.ReadLine();
    if (string.IsNullOrWhiteSpace(input) || input.Equals("exit", StringComparison.OrdinalIgnoreCase))
    {
        break;
    }

    history.Add(new ChatMessage(ChatRole.User, input));

    ChatResponse response = await agent.GetResponseAsync(history, chatOptions);
    history.AddMessages(response);

    // verbosity_level=1: показваме извиканите tools и техните observations
    foreach (ChatMessage message in response.Messages)
    {
        foreach (AIContent content in message.Contents)
        {
            switch (content)
            {
                case FunctionCallContent call:
                    Console.WriteLine($"  Action: {call.Name}({JsonSerializer.Serialize(call.Arguments)})");
                    break;
                case FunctionResultContent result:
                    Console.WriteLine($"  Observation: {result.Result}");
                    break;
            }
        }
    }

    Console.WriteLine($"Alfred: {response.Text}");
}
```
