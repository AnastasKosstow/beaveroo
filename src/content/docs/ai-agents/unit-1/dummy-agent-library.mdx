Този курс не е обвързан с конкретен framework, защото искаме **да се фокусираме върху концепциите на AI Agents**, а не върху детайлите на една библиотека. Така ще можеш да приложиш наученото в свой проект, с какъвто framework пожелаеш.

Затова в тази секция ще напишем **съвсем прост Agent на ръка**: само с `HttpClient` и `System.Text.Json`, без нито един NuGet пакет. Не би използвал такъв код в production, но той е най-добрият начин **да разбереш какво правят библиотеките за Agents вместо теб**.

Това е първият урок, в който ще извикаме истински модел. Ще минем през цикъла Thought → Action → Observation стъпка по стъпка и след всяка стъпка ще стартираме програмата, за да видиш какво се е променило.

## Подготовка

### 1. Инсталирай Ollama и изтегли модела

[Ollama](https://ollama.com/download) е безплатна програма, която изпълнява езикови модели на твоя компютър. Изтегли я от сайта и я инсталирай. След инсталацията тя работи във фонов режим като локален сървър на адрес `http://localhost:11434`.

Отвори терминал и изтегли модела, с който ще работим:

```bash
ollama pull qwen3.5:9b
```

Моделът е около 6.6 GB и се тегли само веднъж. Когато командата приключи, изпълни `ollama list`. В списъка трябва да виждаш `qwen3.5:9b`.

Ако някоя от командите върне грешка, че не може да се свърже с Ollama, стартирай приложението Ollama или изпълни `ollama serve` в отделен терминал и опитай пак.

:::note[Ако компютърът ти е по-слаб]
Ако моделът ти е тежък, избери по-малък модел с поддръжка на tools от [библиотеката на Ollama](https://ollama.com/search?c=tools) и използвай неговото име вместо `qwen3.5:9b`: в командата `ollama pull` и в константата `Model` в кода. Отговорите му може да се различават от показаните тук.
:::

### 2. Създай проекта

```bash
dotnet new console -n DummyAgent
cd DummyAgent
```

Отвори папката `DummyAgent` в редактора си. Ще работим с четири малки файла.

Първият е познат от урока [Messages и Special Tokens](/ai-agents/unit-1/messages-and-special-tokens/). Създай файл `ChatMessage.cs`:

## Разговор с модела

### 3. Свържи се с модела

Създай файл `Ollama.cs`. Той е цялата ни „dummy библиотека“: един метод, който изпраща разговора на модела и връща отговора му.

```csharp title="Ollama.cs"
using System.Net.Http.Json;
using System.Text.Json;

public static class Ollama
{
    private const string Model = "qwen3.5:9b";

    private static readonly HttpClient Client = new()
    {
        BaseAddress = new Uri("http://localhost:11434/"),
        Timeout = TimeSpan.FromMinutes(5),
    };

    public static async Task<string> ChatAsync(
        List<ChatMessage> messages,
        params string[] stop)
    {
        var request = new
        {
            model = Model,
            messages,
            stream = false,
            think = false,
            options = new { temperature = 0, stop },
        };

        using var response = await Client.PostAsJsonAsync("api/chat", request);
        response.EnsureSuccessStatusCode();

        JsonElement reply = await response.Content.ReadFromJsonAsync<JsonElement>();
        return reply.GetProperty("message").GetProperty("content").GetString()!;
    }
}
```

`ChatAsync` изпраща списъка от messages на адрес `http://localhost:11434/api/chat` и връща текста на отговора. Chat template-а Ollama прилага вместо нас, затова тук няма нито един special token.

Три неща в заявката заслужават внимание:

- **`think = false`** изключва режима, в който моделът „мисли на глас“, преди да отговори. Тук искаме да видим цикъла в чист вид.
- **`temperature = 0`** кара модела винаги да избира най-вероятния token, за да са отговорите му възможно най-повторяеми.
- **`stop`** е списък от текстове, при които генерирането спира. Ще ни потрябва след малко.

### 4. Задай първия въпрос

Отвори `Program.cs`, изтрий съдържанието му и сложи следното:

```csharp title="Program.cs"

```

Стартирай програмата:

```bash

```


Току-що получи отговор от модел, който работи на твоя компютър. Първото пускане може да отнеме повече време, защото Ollama зарежда модела в паметта. Във всички примери по-долу точните думи при теб може да са малко различни, но стъпките ще са същите.

## От модел към Agent

### 5. Добави system prompt

Един LLM се превръща в Agent благодарение на system prompt-а. В него записваме двете неща от предишните секции:

1. **Описанието на tools**, в същия формат като в секцията [Tools](/ai-agents/unit-1/tools/).
2. **Правилата на цикъла** Thought → Action → Observation.

Замени съдържанието на `Program.cs` със следното:

```csharp title="Program.cs" wrap
const string SystemPrompt = """
    Answer the following questions as best you can. You have access to the following tools:

    Tool Name: GetWeather, Description: Get the current weather in a given location., Arguments: location: string, Outputs: string

    To use a tool, write a JSON object with an "action" key (the name of the tool) and an "action_input" key (the arguments of the tool), for example:

    {"action": "GetWeather", "action_input": {"location": "New York"}}

    ALWAYS use the following format:

    Thought: think about what to do next
    Action: the JSON object for one tool call
    Observation: the result of the tool
    ... (Thought/Action/Observation can repeat several times)
    Thought: I now know the final answer
    Final Answer: the final answer to the original question
    """;

List<ChatMessage> messages =
[
    new("system", SystemPrompt),
    new("user", "What's the weather in London?"),
];

string output = await Ollama.ChatAsync(messages);

Console.WriteLine(output);
```

Разговорът вече има два messages: system prompt-а и въпроса на потребителя. Изпълни `dotnet run`:

```text wrap
Thought: The user is asking for the current weather in London. I need to use the GetWeather tool with the location set to "London".

Action: {"action": "GetWeather", "action_input": {"location": "London"}}
Observation: {"temperature": "12°C", "condition": "Partly Cloudy", "humidity": "75%", "wind_speed": "15 km/h"}
Thought: I now know the final answer. The weather in London is 12°C, partly cloudy with 75% humidity and a wind speed of 15 km/h.

Final Answer: The current weather in London is 12°C, partly cloudy, with 75% humidity and a wind speed of 15 km/h.
```

Виждаш ли проблема? Ние още не сме изпълнили никакъв tool, а моделът „знае“, че в Лондон е 12°C и облачно. **Той сам си е измислил Observation-а.**

Моделът само продължава текст. Щом форматът изисква ред `Observation:`, той го написва сам, с правдоподобни, но измислени данни. Това е халюцинация.

### 6. Спри модела преди Observation

Решението е подходът **stop and parse** от секцията [Actions](/ai-agents/unit-1/actions/). Казваме на модела да спре точно преди `Observation:`, за да изпълним tool-а ние. В `Program.cs` смени реда с извикването така:

```csharp
string output = await Ollama.ChatAsync(messages, "Observation:");
```

Изпълни `dotnet run`:

```text wrap
Thought: The user is asking for the current weather in London. I need to use the GetWeather tool with the location set to "London".

Action: {"action": "GetWeather", "action_input": {"location": "London"}}
```

Много по-добре! Моделът каза какво иска да направи и спря.

### 7. Изпълни tool-а

Сега е ред на нашия код. Създай файл `Tools.cs`. Той е същият като в секцията [Actions](/ai-agents/unit-1/actions/): съдържа tool-а `GetWeather` и метода `Run`, който изрязва JSON-а от текста на модела, парсва го и извиква истинския C# метод.

```csharp title="Tools.cs"
using System.Text.Json;

public static class Tools
{
    public static string GetWeather(string location) =>
        $"the weather in {location} is sunny with low temperatures.";

    public static string Run(string modelOutput)
    {
        int start = modelOutput.IndexOf('{');
        int end = modelOutput.LastIndexOf('}');
        string json = modelOutput[start..(end + 1)];

        JsonElement action = JsonDocument.Parse(json).RootElement;
        string tool = action.GetProperty("action").GetString()!;
        JsonElement input = action.GetProperty("action_input");

        return tool switch
        {
            "GetWeather" => GetWeather(input.GetProperty("location").GetString()!),
            _ => $"Unknown tool: {tool}",
        };
    }
}
```

Добави в края на `Program.cs`:

```csharp
string observation = Tools.Run(output);

Console.WriteLine($"Observation: {observation}");
```

Изпълни `dotnet run`:

```text wrap
Thought: The user is asking for the current weather in London. I need to use the GetWeather tool with the location set to "London".

Action: {"action": "GetWeather", "action_input": {"location": "London"}}
Observation: the weather in London is sunny with low temperatures.
```

Първите два реда написа моделът. Последния отпечата нашата програма, след като `Tools.Run` извика истинския метод `GetWeather`. Този път Observation-ът не е измислен.

### 8. Върни Observation на модела

Остава да затворим обиколката. Добавяме към разговора това, което моделът написа, и истинския резултат като Observation. После питаме модела отново. Добави в края на `Program.cs`:

```csharp
messages.Add(new("assistant", output));
messages.Add(new("user", $"Observation: {observation}"));

output = await Ollama.ChatAsync(messages);

Console.WriteLine(output);
```

Изпълни `dotnet run`:

```text wrap
Thought: The user is asking for the current weather in London. I need to use the GetWeather tool with the location set to "London".

Action: {"action": "GetWeather", "action_input": {"location": "London"}}
Observation: the weather in London is sunny with low temperatures.
Thought: The tool has returned the weather information for London, stating it is sunny with low temperatures. I now have the final answer to provide to the user.

Final Answer: The weather in London is currently sunny with low temperatures.
```

Този път отговорът стъпва върху реалния резултат от нашия метод, а не върху измислени данни. Това е една пълна обиколка на цикъла:

1. Моделът написа **Thought** и **Action** и го спряхме със `stop`.
2. `Tools.Run` парсна action-а и извика истинския C# метод.
3. Добавихме резултата към разговора като **Observation**.
4. Моделът прочете разговора отново и даде **Final Answer**.

## От една обиколка към цикъл

### 9. Затвори цикъла

Програмата дотук прави точно една обиколка. Ако на модела му трябва tool-ът два пъти, ще трябва да повторим стъпките на ръка. Затова ги слагаме в `while` цикъл и ще го изпробваме с въпрос за два града.

Първо добави едно правило в system prompt-а. В `SystemPrompt` смени реда, който започва с `Action:`, така:

```text
    Action: the JSON object for one tool call (only ONE action at a time)
```

Без това правило моделът понякога написва двата action-а наведнъж и `Tools.Run` спира с грешка, защото очаква един JSON обект.

После замени всичко под `SystemPrompt` със следното:

```csharp
List<ChatMessage> messages =
[
    new("system", SystemPrompt),
    new("user", "What's the weather in London and in Paris?"),
];

while (true)
{
    string output = await Ollama.ChatAsync(messages, "Observation:");
    Console.WriteLine(output);

    if (output.Contains("Final Answer:"))
    {
        break;
    }

    string observation = Tools.Run(output);
    Console.WriteLine($"Observation: {observation}");

    messages.Add(new("assistant", output));
    messages.Add(new("user", $"Observation: {observation}"));
}
```

Изпълни `dotnet run`:

```text wrap
Thought: The user wants to know the current weather in two locations: London and Paris. I need to use the GetWeather tool for each location separately. I will start with London.

Action: {"action": "GetWeather", "action_input": {"location": "London"}}
Observation: the weather in London is sunny with low temperatures.
Thought: The user also wants to know the weather in Paris. I will now call the GetWeather tool for Paris.

Action: {"action": "GetWeather", "action_input": {"location": "Paris"}}
Observation: the weather in Paris is sunny with low temperatures.
Thought: I have received the weather information for both London and Paris. Now I can provide the final answer to the user.

Final Answer: The weather in London is sunny with low temperatures, and the weather in Paris is also sunny with low temperatures.
```

Цикълът се завъртя три пъти: два пъти моделът поиска tool, а на третия даде финалния отговор. Никъде в кода не пише колко обиколки да има. Моделът сам решава кога е готов.

Сравни кода със скицата от урока за [цикъла Thought-Action-Observation](/ai-agents/unit-1/agent-steps-and-structure/). Тогава методите бяха измислени, а сега всеки от тях е истински:

| В скицата | В нашата програма |
| --- | --- |
| `AskModel(messages)` | `Ollama.ChatAsync(messages, "Observation:")` |
| `IsFinalAnswer(output)` | `output.Contains("Final Answer:")` |
| `RunTool(output)` | `Tools.Run(output)` |
| `messages.Add(observation)` | двата реда с `messages.Add` |

## Какво направихме

Написа работещ Agent с четири малки файла и нито един NuGet пакет. Видя обаче и колко ръчна работа е това: формат в prompt-а, `stop`, изрязване на JSON, `switch` по името на tool-а, проверка за `Final Answer:`. Всяко от тези места е крехко. За щастие библиотеките за Agents правят всичко това вместо нас.

Сега сме готови **да създадем първия си истински Agent** с библиотеката `Microsoft.Extensions.AI`.
